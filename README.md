# ESItaClaudeSkills

Особисті скіли Claude Code для роботи з **ITnet2 / ITA**. Вони **не** лежать у
робочій копії ITnet2 і **не** їдуть у TFVC — це окремий git-репозиторій, тож
користуватись ними може будь-хто, незалежно від того, де в нього розгорнуто ITnet2
(і навіть якщо ITnet2 не розгорнуто взагалі).

| Скіл | Що робить | Як викликати |
|---|---|---|
| `changes-description` | короткий опис виконаних змін для вставки в ITA: що виправлено, як тепер працює алгоритм, перелік зачеплених сутностей, склад пакета конфігурації | «опиши зміни», «склад пакета» |
| `worklog-entries` | текстовки для журналу робіт у Notion: розкладка «з — до», без перетинів, у фірмовому стилі | «розпиши в журнал», «розклади по часу» |
| `worklog-setup` | налаштування журналу під **вашу** структуру Notion: зіставлення колонок, поле коду задачі, робочий день | «налаштуй журнал», «онови структуру» |

`worklog-entries` нічого не знає про структуру вашої бази наперед — ідентифікатори, назви
колонок і прапорці живуть у профілі `%USERPROFILE%\.claude\worklog\config.json`, який
створює `worklog-setup`. Перший запуск — з нього.

---

## Встановлення

Два способи. Обидва не залежать від розташування ITnet2 — оберіть один.

### Спосіб 1. Плагін (рекомендую)

Нічого клонувати не треба, оновлення приїжджають самі. У Claude Code:

    /plugin marketplace add trnvdn/ESItaClaudeSkills
    /plugin install es-ita@es-ita-claude-skills

Перезапустіть сесію. Скіли зʼявляться в переліку як `es-ita:changes-description`
і `es-ita:worklog-entries` — або просто попросіть «опиши зміни», і Claude підхопить
потрібний сам.

Оновити пізніше: `/plugin marketplace update es-ita-claude-skills`.
Прибрати: `/plugin uninstall es-ita@es-ita-claude-skills`.

### Спосіб 2. Клон + `setup.ps1` (якщо хочете їх правити)

Для розробки самих скілів: репозиторій лежить, де вам зручно, а в каталог, де Claude
Code шукає скіли, ставляться **junction'и** на його теки. Junction — не копія:
правки одразу діють у Claude, git бачить їх у репозиторії.

    git clone https://github.com/trnvdn/ESItaClaudeSkills.git
    cd ESItaClaudeSkills
    .\setup.ps1

Типово лінкує в `%USERPROFILE%\.claude\skills` — **каталог скілів користувача**, тому
скіли видно з будь-якого проєкту й шлях до ITnet2 ніде не фігурує. Права
адміністратора не потрібні.

Варіанти:

| Команда | Що робить |
|---|---|
| `.\setup.ps1` | підключити всім проєктам (каталог користувача) |
| `.\setup.ps1 -ProjectRoot C:\ITnet2\ITnet2` | підключити лише до цього проєкту |
| `.\setup.ps1 -Name worklog-entries` | підключити один скіл |
| `.\setup.ps1 -Remove` | зняти підключення (сам репозиторій лишається) |

Скрипт ідемпотентний: повторний запуск перестворює лінки. Якщо на місці лінка лежить
**справжній** каталог (наприклад, стара копія скіла), скрипт його не чіпає й пише
попередження — приберіть копію вручну й запустіть ще раз.

Після встановлення перезапустіть сесію Claude Code.

## Розробка

Структура — звичайна для скілів Claude Code:

    .claude-plugin/        манифести плагіна й marketplace (для способу 1)
    skills/<name>/SKILL.md сам скіл: frontmatter (name, description) + інструкція
    skills/<name>/lib/     допоміжні модулі (PowerShell тощо)
    setup.ps1              підключення junction'ами (для способу 2)

Правила, щоб скіл лишався переносним:

- **Жодних шляхів усередину робочої копії ITnet2.** Скіл не знає, де вона і чи є
  взагалі. Власні файли адресувати відносно каталогу скіла
  (`$env:CLAUDE_PLUGIN_ROOT\skills\<name>\...` у режимі плагіна,
  `$env:USERPROFILE\.claude\skills\<name>\...` у режимі junction'ів), робочі —
  у `%USERPROFILE%\.claude\...`.
- **Не покладатись на інші скіли.** Скіли з `$/ITnet2` (`itnet2-*`, `sp-include`)
  можуть бути не підключені. Посилання на них — довідкові, «якщо є».
- `description` у frontmatter — це те, за чим Claude вирішує, чи брати скіл; тригерні
  фрази писати явно, українською і російською.
- Після зміни `SKILL.md` перезапустити сесію — перелік скілів читається на старті.

Версію піднімати в `.claude-plugin/plugin.json` — за нею користувачі бачать оновлення.
